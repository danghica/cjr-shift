GUI reference

The browser interface records shifts, prepares working-time assessments and displays the results of the native CJR core. This reference describes the default browser-storage mode.

Run and use

python3 work/UI/server.py

Open http://127.0.0.1:8765. The native CLI must already be built. Start/stop records the local civil minute; stopping within the same minute is rejected and retains the running shift. Shifts displays completed daily pieces and totals. The menu provides missed shift, compliance, settings and reset; reset requires confirmation.

Settings capture rest arrangements and night-work status. Attendance and regular overtime classifications accompany recorded spans. Compliance supports optional assessment bounds, grouped violations, incomplete evidence and period-specific opt-out declarations. Results are conditional on supplied metadata and the supported profile; breaks are outside scope.

Architecture: core, ports, adapters and bridges

Follow any box to its implementation on GitHub. Arrows show calls and data flow; dashed arrows show proposed-state/save-outcome exchange. Every browser, HTTP, conversion, subprocess and filesystem component lies outside the Rocq proof boundary.

The core's completeStore(true) acknowledges the temporary server-side file save. The browser reports success only after saving the returned complete snapshot to localStorage. The native storage protocol does not prove browser persistence or HTTP delivery.

Source reference

Browser presentation

change; renderReport

Navigation, timer, missed shifts, settings and grouped findings.

Browser storage adapter

createBrowserTransport

Web Lock → read snapshot → HTTP request → atomic localStorage replacement. Save failure keeps the previous snapshot.

Inbound HTTP adapter

make_server / Handler / perform

Validates requests; /api/browser reconstructs a temporary snapshot, dispatches an action and returns the complete next snapshot.

Application bridge

TrackerAdapter; change; compliance

Drives prepare/save/complete, maps user actions and retains metadata outside the tracker encoding.

Native core port adapter

CorePort → core

Runs tracker-core and decodes its JSON response. CorePort is a Python integration abstraction, not a declaration inside the pure core.

Cangjie representation bridge

main; parseState; parseSession; printSession; parseWTMetadata

Dispatches CLI commands; converts civil dates, encoded state/session and metadata into native structures and results back to JSON.

Pure core and ports

TrackerState; TrackerSession; prepareStartShift; completeStore; validateWorkingTime

Tracker operations, storage-protocol transitions and working-time rules. Public functions are the callable ports; storage requests and outcomes are values, not filesystem calls.

Filesystem and metadata adapters

FileRepository; MetadataRepository; save; assess

Locking, atomic file replacement, metadata recovery journal and assessment context/time-zone preparation. In browser mode the files are disposable; localStorage is the durable save boundary.

Action and persistence flow

  1. The browser obtains an exclusive Web Lock and reads cjr-shift.store.v1.
  2. POST /api/browser carries {action, data, snapshot}. A snapshot contains {version, encoding, metadata}; a new browser sends null.
  3. The HTTP adapter reconstructs disposable files and a TrackerAdapter. Start, stop and missed shift call prepareStartShift, prepareEndShift and prepareAddPair. Rejected operations preserve state.
  4. The metadata adapter saves the proposed encoding and metadata. The bridge calls completeStore with the actual file-save outcome. Reset instead saves emptyState and reinitializes the session.
  5. The server returns the complete snapshot and removes temporary files. The browser atomically replaces its localStorage value before showing success. Storage events refresh other tabs.

Storage and assessment limits

Snapshots persist across refreshes and server redeployments within one browser origin. Clearing site data removes them; devices and browser origins do not sync. The server and native executable are required for operations, so recording is unavailable offline. Web Locks and localStorage must be available.

Compliance context is prepared by the Python adapter, then assessed by validateWorkingTime. Attendance and unclassified spans can produce incomplete evidence. Running shifts receive no invented end. A report becomes stale when records or settings change.

The optional --file-store --store /absolute/path/shifts.store mode uses persistent server files and the legacy API. The default GUI uses the browser transport described above.
