Working-time assessment metadata

CLI reference · Example JSON

tracker validateWorkingTime FILE|STATE START END METADATA.json reads a snapshot and reports on the supplied periods. It never changes shifts or their store. File mode uses the existing sibling lock file. Successful assessment exits 0; domain results other than 0 exit 1; argument, file and representation errors exit 2.

Scope and caller obligations

The accepted narrower interface trusts the caller to identify every statutory period and determine legal applicability. It does not infer opt-outs, employment dates, working-day boundaries, reference-period agreements, hazardous duties or night-worker status from shifts. The pure core computes all sums, gaps and comparisons. Code 0 is conditional on accurate classifications and complete periods; it is not a certificate of UK legal compliance.

No break records, aggregate break durations or assumed deductions are accepted. Every report marks in-work breaks not_assessed with reason outside_scope. If recorded spans cannot be classified as actual working time, set elapsedWorkKnown=false; do not invent a deduction.

Top-level JSON object

Every key below is required; extra keys are rejected. Boolean values must be JSON true/false. Timestamps are ordinal minute integers or Gregorian YYYY-MM-DDTHH:MM strings. The core uses elapsed-minute coordinates; the adapter performs no timezone or daylight-saving conversion. Supply a consistent elapsed timeline and the statutory calendar duration separately. Every numeric timestamp and calendar duration is bounded to 6000000000. Interval and period lists contain at most 10000 items; native stack and memory limits may require smaller lists.

  • jurisdiction: "GB", "NI" or "unknown". Unknown, under-18 or special regimes return 22.
  • adult, ordinaryRegime: applicability flags for the ordinary adult regime.
  • coverageStart, coverageEnd: bounds of history known to include all work, including other employment. Missing history must not be zero-filled.
  • periodCoverageComplete: caller attests every relevant legal assessment period is supplied. False forces incomplete result 21 unless a confirmed violation takes precedence. All five rule categories must also be present. This structural check cannot verify that a rolling-window list is exhaustive.
  • elapsedWorkKnown: whether the recorded spans have known actual-working-time meaning and elapsed durations. False makes applicable periods incomplete.
  • otherWork: sorted, disjoint [start,end] pairs of additional actual working time; must not overlap stored work. Include all qualifying overtime and work for other employers.
  • normalWork: sorted, disjoint intervals of normal hours for the night average, including regular overtime where legally required. Must be a subset of combined work.
  • weeklyRest: sorted, disjoint statutory weekly-rest intervals to exclude from the night-average denominator. Must not intersect work. These are weekly-rest entitlements, not tracked in-work breaks.
  • nightWork: sorted, disjoint work intervals classified as night work under the applicable statutory/agreed night period. Must be a subset of combined work. Ordinary night-worker classification and hazardous-work applicability are declared per assessment period. The usual night period is 23:00–06:00; an agreed alternative must last at least seven hours and include 00:00–05:00. Night-worker classification normally concerns regular work of at least three hours during night time; an occasional shift crossing midnight does not by itself establish it. The caller must apply the statutory definition, including relevant collective/workforce arrangements.
  • periods: list of the objects described below. Order is preserved in findings.

Each period

Required keys: rule, start, end, calendarMinutes, extraStart, extraEnd, evidence, restScheme, dailyRestOverlap. Start must precede end; periods must overlap the requested assessment range. The core checks each supplied period in full, not clipped to the requested range.

evidence is "known" (applicable and all classification facts known), "unknown" (incomplete, 21), "not_applicable" (caller establishes inapplicability), or "unsupported" (22). An effective valid weekly opt-out can justify not_applicable for rule 101 only; it does not waive night limits. An exception requiring compensatory rest or another unsupported legal regime must not be labelled not_applicable merely to pass.

  • 101 weekly average: reference-period actual endpoints; calendarMinutes is the statutory reference period in calendar days × 1440 (normally 17 × 7 × 1440). The core compares (work + replacementWork) × 10080 against 2880 × calendarMinutes. For statutory excluded days, identify the worked replacement span after the reference period as extraStart/extraEnd; otherwise use equal extra endpoints. Caller must establish excluded-day/replacement eligibility and completeness. The core verifies coverage and counts work in the supplied span.
  • 102 daily rest: an applicable 1440-minute working period, identified from duty/day context, not every arbitrary sliding window or every midnight piece. Core requires a continuous 660-minute gap. Adjacent pieces do not create rest.
  • 103 weekly rest: restScheme=1 for one 24-hour entitlement in a 7-day period (calendarMinutes=10080); 2 for two 24-hour entitlements in a fortnight, with a single continuous 48-hour entitlement also sufficient; 3 for one 48-hour entitlement in a fortnight (calendarMinutes=20160). The actual endpoints encode the legal calendar window across clock changes. Core normally adds 660 minutes of daily rest to each separate entitlement; dailyRestOverlap=true asserts the statutory objective/technical/work-organisation justification for overlap. Do not set it for convenience.
  • 105 average night work: caller establishes night-worker status and applicable reference period. Core compares normalWork × 1440 against 480 × (calendarMinutes − weeklyRest). Nonpositive denominator is invalid (20). Supply all statutory weekly rest for that denominator.
  • 106 hazardous night work: each relevant 1440-minute period under the strict rule. Where classified night work intersects it, all actual work in it must be ≤480 minutes. Caller establishes special hazards/heavy strain and supplies every affected window.

Unused restScheme may be 0; unused extraStart/extraEnd should be equal. All duration comparisons are minute-resolution. Evidence categories, statutory period choices and calendar adjustments are trusted input facts rather than verified legal determinations.

Result JSON

code, message, findings, breaksAssessed, excludedChecks. Every finding carries rule, code, period start/end, measured, limit and unit. Findings preserve all supplied periods, including successes. 101/105 use scaled_comparison operands (not hours); 103 uses rest_periods; 102/106 use minutes. An unknown/unsupported/not-applicable period has zero operands, which are placeholders rather than measurements.

Codes: 0 conditional success; 20 invalid metadata; 21 insufficient information/classification/coverage; 22 unsupported; 101 weekly hours; 102 daily rest; 103 weekly rest; 105 average night hours; 106 hazardous night hours. 104 is reserved and never emitted. The summary selects the lowest confirmed violation first, otherwise invalid, unsupported, incomplete, then success. Invalid top-level representation returns no per-period findings. A pending shift before a period ends makes that period incomplete; for 101 the replacement span also matters.

Example

The example intentionally has periodCoverageComplete=false: its short illustrative period list is not a full legal assessment. This read-only invocation returns 21 for empty state:

work/CLI/bin/tracker validateWorkingTime '-|' @0 @171360 work/CLI/example-working-time.json

Statutory traceability

Great Britain: Working Time Regulations 1998, Part II, regulations 4–6 and 10–12. Northern Ireland: Working Time Regulations (NI) 2016. The ordinary regimes use the same supplied-period calculations here; regime selection and exceptional provisions remain metadata obligations. See also government night-work guidance.
